# Installation

Use a dedicated development environment and a new, explicit version prefix. Do not overwrite an existing installation to try this unreleased version.

Python source installation:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install ./packages/frameviz-py
```

For an independently built wheel, install its explicit path inside a virtual environment. Offline installation also requires compatible wheels for numpy and websocket-client; a source archive alone is not a complete offline distribution.

C++ source installation:

```sh
cmake -S packages/frameviz-cpp -B .cache/cpp-release \
  -DCMAKE_BUILD_TYPE=Release -DFRAMEVIZ_BUILD_TESTS=OFF \
  -DCMAKE_INSTALL_PREFIX="$PWD/.local/sdk"
cmake --build .cache/cpp-release
cmake --install .cache/cpp-release
```

Consumers use `find_package(frameviz 0.4.0 EXACT CONFIG REQUIRED)`, `frameviz::cpp`, and an explicit `CMAKE_PREFIX_PATH`. The install includes the selected transport library, headers, and license notices. Normal platform dependencies such as system threads and zlib may still be required.

Vue consumers use the three local SDK tarballs generated by `scripts/release/pack-js-sdk-tarballs.sh`. The devkit builder rewrites dependencies to its packaged tarballs. Do not assume registry versions have been published.

The portable installer verifies every manifest-listed file before installing into a prefix that does not exist. Uninstall deletes only unchanged owned files, preserves modified/user files and new empty directories, and does not modify shell profiles or global Python. It stages supplied packages; it does not claim to deploy and register a complete native runtime. Native installer/upgrade behavior must be accepted separately.

One Host owns each state directory. To run multiple Hosts, give every process and its clients a distinct `FRAMEVIZ_HOME` (or explicit discovery path), port, and log directory. Defaults are `~/.local/share/qqfly/frameviz` on macOS/Linux and `%LOCALAPPDATA%/qqfly/FrameViz` on Windows. Legacy state directories and global application names are not searched.

## Linux runtime discovery

Install the FrameViz runtime `.deb` once, then install the Python SDK wheel into each virtual environment that needs it. With a desktop session, the normal entry point is:

```python
import frameviz as fv
viz = fv.open()
viz.add_box()
```

No source checkout or executable-path variable is needed for the standard `.deb` installation. Python checks the known installed executable `/usr/bin/frameviz` before falling back to release/debug binaries in a source tree whose `project_id` and protocol version match this SDK. An installed candidate must be an executable file. SDK startup runs it with `--headless`; opening the scene window uses the existing authenticated control connection, so startup does not display the welcome page.

An explicit `FRAMEVIZ_TAURI_APP` overrides the automatic application search. `frameviz.host.find_host_executable()` also accepts `FRAMEVIZ_HOST_PATH`. Executables with the same name in an arbitrary `PATH` directory are not auto-selected. A missing or non-executable system installation does not prevent the source-build fallback. Wire-protocol compatibility is still checked when connecting.

This describes the discovery contract, not a claim that a particular Ubuntu installation or graphics driver has passed desktop acceptance. Clean Ubuntu 22.04/24.04 `.deb` installation and native-window checks are separate from simulated discovery tests.

Apple Silicon native preview installation, signing status, paired SDKs and source reproduction are documented in [MACOS.md](MACOS.md).
